# Reproduction manifest

Evaluation always runs on a single GPU; pass `--gpu N` to choose it.

Every retained code-produced artifact in the main paper, supplement and final rebuttal is listed below. Commands are run from the repository root. Model files are local aliases from [CHECKPOINTS.md](CHECKPOINTS.md); its download links require access to the private model repository until the camera-ready. Full training, conversion, statistics over paper outputs and full evaluation were **not executed here**. The documentation gate checks shell help/dry-run commands and composes their Hydra arguments, and checks Python tools with `--help`.

Standard HRRC scores 1×/2×/4× against bicubic GT. With `--images`, the 8×-only pass writes predictions only; `*_gt.png` and `input_*.png` come from the standard `--images` pass. The separate `--8x` pass renders 1×/8× and scores 8×, with metric suffixes none/2/3/4 denoting 1×/2×/4×/8×. Per-scene arrays are aligned positionally by `metrics/scenes_all.json`; never sort scores independently. Black-hole fraction uses rendered max RGB < ε and GT max RGB > ε, with max RGB as the luma proxy; ε is 0.02 with a 0.01/0.02/0.05 sweep. Accumulated-alpha coverage is a separate diagnostic.

**ScanNet protocol (supplement section 3):** SurfSplat’s split is unreleased. Our zero-shot protocol follows its slicing convention (nominal 350 frames, 20-frame overlap, merging a tail shorter than 100 frames), and generates the shared index using the repository’s overlap geometry at seed 0: 635 slices, 633 with GT depth. The shipped `assets/evaluation_index_scannet.json` is the protocol of record; `generate_scannet_eval_index.py` reproduces it verbatim from the raw poses. Its numeric frame ordering differs from `convert_scan.py`’s lexicographic chunk ordering for non-zero-padded frame names, so a regenerated index must be paired with chunks produced by this converter, as the shipped index was. The index/chunk pairing is fixed by the shipped files. Rendered-normal error is the geometry measure. Rebuttal Table A intersects valid pixels, then aggregates slice-level differences by physical scene; no reference sample count or p-value is forced by the tools. ScanNet index regeneration was not executed here. It requires raw ScanNet data, absent from the validation environment.

**DL3DV protocol (main Table 2):** evaluation resolution is 256×256, source dimensions remain 270×480, near/far is 0.5/200 and the frozen index has two context / four target views. `skip_bad_shape=true` omits one inconsistent-shape scene, leaving 139 scenes. After converting the chunks, generate the scene-key-to-chunk mapping required by the loader:

```bash
python src/scripts/generate_chunk_index.py --root datasets/dl3dv/test # not executed here
```

For the main HRRC significance results, run each scale’s PSNR/SSIM/LPIPS as a separate Holm family, as in M5.
